# Решавање на Bug во Gitflow Workflow

Во ова сценарио, се наоѓаме на `master` гранката и треба да решиме bug што предизвикува 404 грешка при клик на копче. Ќе користиме Gitflow workflow за да го поправиме проблемот.

## Чекори за решавање на проблемот

### 1. Создавање на `hotfix` гранка

```sh
 git checkout -b hotfix
```

**Објаснување:** Отвораме нова `hotfix` гранка за да го поправиме проблемот без да влијаеме на тековниот развој.

### 2. Поправка на кодот и зачувување на промените

```sh
git add & git commit -m "some message"
```

**Објаснување:** Ги додаваме и зачувуваме промените во Git со јасна commit порака.

### 3. Враќање на `master` гранката

```sh
git checkout master
```

**Објаснување:** Преминуваме на `master` за да го споиме поправениот код.

### 4. Спојување на `hotfix` во `master`

```sh
git merge --no-ff hotfix
```

**Објаснување:** Спојуваме (`merge`) со опцијата `--no-ff` за да зачуваме историја дека ова е hotfix.

### 5. Тагирање на новата верзија

```sh
git tag -a 2.1.1
```

**Објаснување:** Додаваме нов таг за да означиме дека ова е нова фиксна верзија на софтверот.

### 6. Враќање на `develop` гранката

```sh
git checkout develop
```

**Објаснување:** Преминуваме на `develop` за да го внесеме поправениот код и во гранката за развој.

### 7. Спојување на `hotfix` во `develop`

```sh
git merge --no-ff hotfix
```

**Објаснување:** Ја спојуваме `hotfix` гранката во `develop` за да осигураме дека поправката ќе биде вклучена и во идните верзии.

### 8. Бришење на `hotfix` гранката

```sh
git branch -d hotfix
```

**Објаснување:** Гранката `hotfix` веќе не е потребна, па ја бришеме за да го одржуваме репозиториумот чист.
