# Вовед во Git (Git Real Lvls: 1, 2, 3, 4, 5, 6)

## Level 1

### GIT HELP

**`git help`**  
Оваа команда ја прикажува документацијата за различни git команди.

**`git help config`**  
Со оваа команда добиваме детален водич за тоа како да го конфигурираме git на нашиот систем.

---

### Конфигурирање на Git

За да го конфигурираме git, користете ги следниве команди:

- **`git config --global user.name "Ваш username"`**  
  Поставува глобален username за вашиот git.

- **`git config --global user.email "Вашиот email"`**  
  Поставува глобален email за вашиот git.

---

### Основни Git команди

- **`git init`**  
  Иницијализира нов, празен git repository во тековниот директориум.

- **`git status`**  
  Покажува моменталната состојба на нашето git репозиториум. Прикажува кои фајлови треба да се додадат во staging area и кои се подготвени за commit.

- **`git add <file>`**  
  Додава конкретен фајл во staging area, подготвувајќи го за commit.

- **`git commit -m "Message"`**  
  Создава commit во git репозиториумот со дадената порака (на примерот: "Message").

- **`git add --all`**  
  Додава сите фајлови во staging area, вклучувајќи нови, изменети и избришани фајлови.

- **`git add .`**  
  Слично на претходната команда, но не ги додава избришаните фајлови. Додава само нови и изменети фајлови.

- **`git add *.txt`**  
  Додава сите фајлови со екстензија **.txt** во staging area од тековниот директориум.

- **`git add docs/`**  
  Додава сите фајлови во директориумот **docs/** во staging area.

- **`git add "*.txt"`**  
  Додава сите фајлови со екстензија **.txt** во staging area, користејќи кавички за да избегнете проблеми со shell интерпретацијата.

- **`git log`**  
  Прикажува историја на сите commits направени во репозиториумот. Вклучува информации за commit ID, автор, датум и порака за commit.

## Level 2

- **`git diff`**  
  Се користи за разликите помеѓу различни верзии на фајловите во Git repo-то ова кажува кои линии се променети во однос на последниот commit или помеѓу други верзии на фајлот.

- **`git diff --staged`**  
  Ова прикажува разликите за фајловите што се додадени во staging area односно ова прикажува разлики што ќе бидат дел од следниот commit во споредба со последниот commit.

- **`git reset HEAD <file>`**  
  Ова се користи за да го остарни дадениот фајл или фајлови од staging area, т.е. го враќа фајлот во неговата претходна состојба пред да биде додаден во staging area, без да направи било каква промена на самиот фајл.

- **`git checkout -- <file>`**  
  Оваа команда се користи за да ги откажете локалните промени што сте ги направиле на дадениот фајл и да го вратите во состојба каква што бил во последниот commit на тековната гранка.

- **`git commit -a -m "Message"`**  
  Тука -а автоматски додава сите изменети фајлови во staging area, така што не треба рачно да користиме git add за да ги додадеме. (не ги додава untracked фајловите)

- **`git reset --soft HEAD~1`**  
  Ова се користи за да го вратите HEAD за еден commit назад, без да ги изгубите промените што сте ги направиле во staging area.

- **`git commit --amend -m "Message"`**  
  Се користи за измена на последниот commit што сте го направиле. Оваа команда ви дозволува да ја промените порака на последниот commit или да додадете нови измени во него.

---

### **`--soft`, `--hard`**

Командата **`git reset`** има три главни опции: **`--soft`**, **`--mixed`**, и **`--hard`**, кои влијаат на начинот на кој се враќа **HEAD** и како се менува состојбата на **staging area** и **working directory**. Секој од овие опции има различен ефект на вашата локална историја и промените.

#### 1. **`git reset --soft`**
- **`--soft`** ја менува **HEAD** (позицијата на гранката) на одреден commit, но **задржува сите промени** во **staging area** (фајловите остануваат подготвени за нов commit).
- **`--soft`** не го менува **working directory**.
- Ова е корисно кога сакате да го откажете последниот commit, но да ги оставите промените во staging area за понатамошно работување.
- Можете да користите **`HEAD~1`** (или **`HEAD^`**) за да се вратите еден commit назад или **`HEAD~2`** (или **`HEAD^^`**) за два commits назад.

#### 2. **`git reset --hard`**
- **`--hard`** ја менува **HEAD** на одреден commit и **целосно ги чисти** и **staging area** и **working directory**.
- Ова значи дека сите локални промени што не сте ги зачувале ќе бидат изгубени.
- Ова е многу моќна и ризична опција, бидејќи може да доведе до губење на податоци.
- Можете да користите **`HEAD~1`** (или **`HEAD^`**) за да се вратите еден commit назад или **`HEAD~2`** (или **`HEAD^^`**) за два commits назад.

### Git Remote Commands

**`git remote add origin <линк до repo-то>`**  
Оваа команда го додава далечниот repo созададено на GitHub, GitLab итн. на нашиот локален git repo. Ова поставува линк на repo-то кој се користи за синхронизација помеѓу локалниот и далечниот repo. Далечниот repo се нарекува origin.

**`git remote -v`**  
Ова команда се користи за прикажување на далечниот repo кои се поврзани во нашиот git repo.

**`git push -v origin master`**  
Ова команда се користи за пуштање на локалните промени во далечниот repo.  
- **`git push`**: Ова е основната команда за испраќање на локалните промени во далечниот repo. Ова ги пренесува локалните промени на сервер.
- **`-v`**: Ова е опција verbose. Кога ќе ја додадете, git ќе прикаже повеќе информации за процесите на испраќање, детални инфромации.
- **`origin`**: Ова е име на далечниот repo-то.
- **`master`**: Ова е името на гранката во локалниот репозиториум.

**`git pull`**  
Ова команда се користи за повлекување на најновите промени од далечниот repo во нашиот локален repo.

### Git Remote Add, Remove and Push

**`git remote add <name> <address>`**  
- Додава нов далечен репозиториум во вашиот локален репозиториум.
- **`<name>`** е името на далечниот репозиториум (најчесто **`origin`**).
- **`<address>`** е URL-то на далечниот репозиториум.

**`git remote rm <name>`**  
- Ги отстранува далечните репозиториуми од вашиот локален репозиториум.
- **`<name>`** е името на репозиториумот што сакате да го отстраните.

**`git push -u <name> <branch>`**  
- Пушта локални промени во далечниот репозиториум на конкретна гранка.
- **`<name>`** е името на далечниот репозиториум (најчесто **`origin`**).
- **`<branch>`** е името на гранката која ја пуштате.

### Зошто не треба да користите `git reset --soft`, `git reset --hard`, или `git commit --amend` по `git push`

**`git reset --soft <commit>`**  
- Ова ја менува **HEAD** на дадениот commit, но ги задржува промените во **staging area**. Потребно е да ги пуштите промените откако ќе ги направите.

**`git reset --hard <commit>`**  
- Ова ја менува **HEAD** на дадениот commit и ги чисти сите локални промени, вклучувајќи ги оние во **working directory** и **staging area**. Промените кои не се зачувани ќе бидат изгубени.  
- Ова може да доведе до губење податоци ако не сте внимателни.

**`git commit --amend`**  
- Ова ја менува порака на последниот commit или додава нови промени во него.
- Ако користите ова по `git push`, и го промените комитот, ќе треба да направите force push.  
- Ова може да го наруши интегритетот на историјата на репозиториумот, особено ако се работи на проект со други луѓе.

## Level 3

**`git clone <repo-url> <folder>`**  
Оваа команда ја користиме за клонирање на Git репозиториум. URL-то на репозиториумот може да биде во HTTPS или SSH формат. `<folder>` е опционален параметар, кој се користи за да се определи во кој фолдер (папка) ќе се клонира репозиториумот. Ако не се укаже фолдер, репозиториумот ќе биде клониран во фолдер со исто име како репозиториумот.

**`git branch <name-branch>`**  
Оваа команда се користи за создавање нова гранка со име `<name-branch>` во вашиот локален репозиториум.

**`git branch`**  
Оваа команда се користи за листа на сите локални гранки и ќе ја означи тековната гранка со `(*)`.

**`git checkout <branch-name>`**  
Оваа команда се користи за менување на гранката.

**`git merge <branch-name>`**  
Оваа команда се користи за спојување (**merge**) на гранката `<branch-name>` во тековната гранка.

**`git branch -d <branch-name>`**  
Оваа команда се користи за бришење на локална гранка во Git. `-d` ја бриши гранката ако таа е веќе споена со друга гранка.

**`git checkout -b <branch-name>`**  
Создава нова гранка со името `<branch-name>` и веднаш се префрла на неа.

## Level 4|5
**`git fetch`**
Командата ги презема најновите промени од далечниот репозиториум без да ги спои со вашата локална гранка.

**``git remote prune origin``**
E команда која ги брише локалните референци на гранки кои повеќе не постојат на дакечниот репозиториум (на пример, ако некој ги избришал тие гранки на серверот). Ова помага да се одржи чистота на локалниот репозиториум и да се отстранат неактивните гранки кои не се потребни.

**``git tag``**
E команда која се користи за управување со тагови во Git. Таговите се обично користат за означување на специфицирани точки во историјата на проектот, како што се издавања на верзии или важни настани.

**``git tag -a vx.x.x -m "version x.x.x"``**
За додавање на нов таг и потоа се прави `git push --tags` за да ги испратиш таговите до серверот

**``git rebase``**
E команда во Git која се користи за преместување или прераспоредување на една гранка врз друга. Таа е алтернатива на `git merge`, но го прави процесот на спојување поблиску до линеарно, без дополнителни merge commit-и
